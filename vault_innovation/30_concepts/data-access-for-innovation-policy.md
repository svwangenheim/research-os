# Data Access for Innovation Policy

## Definition

Data access for innovation policy refers to the availability, usability, legal clarity, interoperability, and governance of data that enable innovation, AI adoption, research commercialization, policy evaluation, and evidence-based steering. It includes public-sector data, research data, administrative funding data, industrial data spaces, health/agriculture data, patent and IP data, and evaluation datasets.

## Scope boundaries

This concept includes data as innovation infrastructure and data as evaluation infrastructure. It covers rules for access and sharing, data spaces, data trusteeship, research data centers, public-data publication, administrative data linkage, and the data needed to evaluate policy effects.

It does not include every dataset note. Specific data resources should have their own dataset notes when they recur across sources, for example [[50_datasets/foerderkatalog-des-bundes.md]] and [[50_datasets/mannheimer-innovationspanel.md]].

## Mechanism

Data access affects innovation through several channels:

- firms need data to build and deploy AI, digital, and smart technologies;
- researchers and evaluators need linked data to estimate policy effects;
- public data can enable new products, services, and scientific work;
- data uncertainty and fragmented legal interpretation can slow adoption;
- poor administrative data makes it hard to learn which programs work.

EFI 2023 and EFI 2024 both argue that data access is a central bottleneck for the German F&I system. EFI 2024 links data access directly to causal evaluation: without better data availability and publication of evaluation studies, policy learning remains weak.

## How it is measured

Useful indicators include:

- availability of administrative, project, outcome, and firm-level data;
- ability to link funding records to outcomes;
- existence and usability of public data portals, research data centers, data spaces, and data trustees;
- legal clarity under data protection, statistics, tax, health, and sectoral rules;
- adoption of data-intensive technologies such as AI;
- quality and reproducibility of evaluation studies.

## How the papers use the concept

EFI uses data access as a policy-infrastructure bottleneck. Heimberger et al. use data/digital capabilities as adoption conditions for AI in production. Krieger uses project text as an input for semantic and machine-learning classification of policy portfolios. The Foerderkatalog project uses data access as a practical condition for TRL and technology classification.

## Open questions and tensions

- Strong data access must be balanced with privacy, security, trade secrets, and public trust.
- Data availability does not guarantee policy learning unless evaluation designs are credible.
- Open data can support innovation, but industrial data spaces may require governance models that solve incentives for sharing.
- LLM/AI workflows can classify project texts, but only if source data are complete, stable, and documented.
